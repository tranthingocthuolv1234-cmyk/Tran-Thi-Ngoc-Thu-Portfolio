01

OVERVIEW

Problem and context

Students and early-career candidates often need repeated interview practice, but access to timely, consistent feedback can be limited. Self-practice also makes it difficult to recreate the pressure and conversational rhythm of a live interview.

VirtuHire explored how a guided VR environment, voice interaction, and AI-supported analysis could create a more structured practice loop. The academic project focused on clarifying the core experience and the system behavior required to support it.

01

Realistic practice

Create an interview flow that feels guided without removing the candidate’s agency.

02

Voice reliability

Make capture, transcription, processing, and playback states understandable.

03

Useful feedback

Turn answer analysis into specific, reviewable improvement guidance.

04

Recoverable errors

Define clear fallback behavior when audio or AI services are unavailable.

Design question

How might we help candidates practise interviews in an immersive environment while receiving feedback that is clear, consistent, and actionable?

02

ROLE

Requirement analysis

Clarified core user needs, functional behavior, error states, dependencies, and unresolved decisions.

Experience modeling

Mapped the candidate journey from setup to feedback and identified moments of uncertainty.

System modeling

Connected user actions with Unity, backend, speech, language-model, and voice-response interactions.

Validation support

Reviewed prototype screens against selected requirements and documented questions for future testing.

06

USER STORIES

US-01 Configure an interview session

As a candidate, I want to configure my interview language and target position so that the practice session matches my needs.

  • Given the candidate opens setup, when the options load, then available languages and positions are displayed and can be selected.
  • Given required setup is complete, when Start Interview is selected, then the simulation begins.
  • Given setup is incomplete, when the candidate attempts to start, then clear validation is shown.
US-02 Enter a guided VR interview

As a candidate, I want to enter a guided VR interview environment so that I can practise in a more realistic context.

  • Given the environment loads, when the scene is ready, then the interview setting is displayed.
  • Given the interview begins, when the first question is ready, then the system presents it.
  • Given the interview is active, when the candidate continues, then the system guides them through the defined flow.
US-03 Answer by voice

As a candidate, I want to answer interview questions by voice so that the practice resembles a spoken interview.

  • Given a question is presented, when the candidate begins speaking, then the system captures the voice input.
  • Given the candidate finishes, when the answer is submitted, then it is sent for speech-to-text processing.
  • Given transcription succeeds, when text is returned, then it is sent for AI analysis.
  • Given voice capture or transcription fails, then a clear message and retry path are shown.
US-04 Receive AI-supported analysis

As a candidate, I want my answer analyzed against consistent dimensions so that I can understand its quality.

  • Given answer text is available, when analysis begins, then predefined dimensions are applied.
  • Given analysis succeeds, when results return, then relevance, clarity, structure, and communication are included.
  • Given analysis fails, then the system presents a useful fallback state.
US-05 Review structured feedback

As a candidate, I want structured feedback after answering so that I know what to maintain and improve.

  • Given analysis is complete, when feedback is generated, then it follows a consistent structure.
  • Given feedback is displayed, when the candidate reviews it, then strengths, weaknesses, and improvement guidance are visible.
  • Given feedback is invalid or a service issue occurs, then a fallback message is shown.
US-06 Review a performance report

As a candidate, I want a performance report so that I can review the session and plan another practice attempt.

  • Given the session is complete, when the result is opened, then a performance report is displayed.
  • Given the report is visible, when it is reviewed, then a summary and suggestions are available.
  • Given the candidate chooses to practise again, when returning to setup, then a new session can be configured.

07

WORKFLOW

  1. 01

    Capture

    The candidate records and submits a spoken answer in the Unity experience.

  2. 02

    Transcribe

    The backend sends audio to speech-to-text and returns a transcript.

  3. 03

    Analyze

    The transcript and interview context are sent to the language model.

  4. 04

    Respond

    Structured feedback is returned; text-to-speech can provide an audible response.

  5. 05

    Review

    The candidate reviews feedback and the summarized performance report.

Artifact purpose

Make integration responsibilities and alternate flows visible.

Key decision

Separate capture, orchestration, and AI services so each state can be handled clearly.

Open questions

Acceptable latency, retry limits, transcript editing, data retention, and model-output safeguards.

08

USE CASE

Candidate-facing functions

  • Configure interview
  • Start and navigate a session
  • Answer questions by voice
  • Review feedback and performance

AI-supported functions

  • Convert speech to text
  • Analyze answer content
  • Generate structured feedback
  • Return an audible response

The use case model supported requirement traceability by separating user goals from the external services needed to complete them. It also highlighted failure paths that require explicit requirements rather than assuming every AI request succeeds.

10

OUTCOMES

The project produced a working academic prototype and a clearer set of product artifacts. Validation in this case refers to reviewing consistency between the intended flow, documented requirements, diagrams, and visible prototype states; it does not represent a formal candidate pilot.

What the artifacts clarified

  • The end-to-end candidate practice loop
  • Responsibilities across interface, backend, and AI services
  • Traceability from selected requirements to prototype screens
  • Failure paths needing explicit user feedback

What remains unvalidated

  • Candidate comprehension and comfort in VR
  • Feedback usefulness and trust
  • Acceptable end-to-end response time
  • Scoring consistency across roles and languages

11

LESSONS

What I learned

  • AI features need conventional product requirements as much as they need prompts and models.
  • Waiting, error, and retry states are part of the core journey.
  • Diagrams become more useful when each one supports a concrete product decision.
  • Academic assumptions should remain clearly separated from validated user evidence.

Recommended next steps

  1. Run moderated usability sessions with target candidates.
  2. Review question and feedback criteria with an HR subject-matter expert.
  3. Define latency, accessibility, privacy, and data-retention requirements.
  4. Test transcript correction and fallback interactions.
  5. Refine report language based on comprehension testing.
